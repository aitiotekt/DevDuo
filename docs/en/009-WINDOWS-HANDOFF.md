# Windows handoff

Windows exclusively uses the pinned WebKit Windows Port through Avalonia. Preserve system WKWebView on macOS and both Safari shell and immersive containers. The [WebKit guide](014-WINDOWS-WEBKIT.md) owns runtime source, reproduction and detailed limitations; host controls follow the [roadmap](100-ROADMAP.md).

## Setup and platform code

Follow [Contributing](../../CONTRIBUTING.md), including real file/directory symlinks and `core.symlinks=true`. Build the required runtime with `mise --env windows-webkit exec -- just build-windows-webkit-runtime` after installing that mise environment. Visual Studio C++/Clang and Windows SDK remain system dependencies. `just dev` automatically discovers `temp/build/windows-webkit-host/bin`; an absolute `DEVDUO_WEBKIT_RUNTIME` overrides the location. An invalid runtime fails explicitly. The measured page exclusively uses WebKit; only the separate developer-tools frontend uses system WebView2. Do not rewrite macOS locks for Windows-only changes.

The official Windows WebKit `324423@main` probe supplied the baseline for the source-built application runtime. Color-extension eligibility/history is distinct from stale document pixels. These observations use fixture `scrollTo`, not an independently repeated Windows wheel test. Original window PNGs, DOM records and fixture sources are local under `captures/desktop-validation/document-end/`.

For a top-zero, unzoomed scene, let `D` be the root document height, `Y` actual scrollY, `V` the unobscured viewport height and `B` the bottom inset. Valid continuation length is `L = clamp(D - Y - V, 0, B)`. Preserve live content in `[V, V+L)` and explicitly clear/fill `[V+L, V+B)` in the final native rendering surface on each relevant update. Here the fill starts appearing after `2400 - 580 - 98 = 1722`. Keep `D`, `V`, the scroll range and fixed frames unchanged; adding DOM padding or filling the whole inset prematurely hides valid content. Convert CSS coordinates through the actual zoom/DPI transform. Painting only the parent HWND background will not remove stale pixels retained by an opaque child/backing surface.

Use the engine's resolved under-page/canvas background, with an explicitly labeled html/body background fallback; do not copy the last numbered row or use the toolbar theme tint as the page background.
