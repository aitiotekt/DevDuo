# 应用本地化

DevDuo 桌面应用提供英语和简体中文。**语言**控件包含**跟随系统**、**English** 和**简体中文**。切换语言时，宿主控件、状态消息、原生外壳标签、离线欢迎页和颜色实验室会就地更新，不会重新加载或替换已加载的 WebView。

## 选择与持久化

初始选项为跟随系统。应用启动时，根据操作系统的界面区域性确定语言：

| 系统界面区域性 | 应用语言 |
| --- | --- |
| 中文，包括 `zh`、`zh-CN`、`zh-SG` 和 `zh-Hans` 区域性 | 简体中文 |
| 名称包含 `Hant`，或为 `zh-TW`、`zh-HK`、`zh-MO` | 英语 |
| 其他区域性，包括固定区域性 | 英语 |

手动选择英语或简体中文优先于系统设置。跟随系统使用启动时读取的界面区域性；修改操作系统界面语言后，应重启应用。

偏好设置位于当前用户的 .NET `LocalApplicationData` 目录下的 `DevDuo/preferences.json`，与仓库配置和浏览器配置文件分开。该文件由 `Host/PreferenceStore.cs` 管理。JSON 包含 `schemaVersion: 1`、值为 `system`、`en` 或 `zh-Hans` 的 `language`，以及保存宿主设置的可选 `host` 对象（见[架构](001-ARCHITECTURE.md)）。写入通过临时文件替换完成；写入语言时保留宿主设置，写入宿主设置时保留语言。读取器仅接受包含整数 `schemaVersion: 1` 和字符串 `language` 的 JSON 对象，允许额外字段，因此早期只含语言的文件仍然有效。非对象根节点、缺失或不支持的版本、缺失或非字符串语言字段均回退到跟随系统，并显示本地化说明。未知的语言字符串也回退到跟随系统。偏好文件不存在时跟随系统；无法读取或文件损坏时也会回退，并显示说明。`host` 中单个字段无效时回退为默认值，并在说明中列出字段名，不影响语言。如果保存失败，所选语言仍在本次会话生效。偏好设置消息显示在设置侧栏的**重置设置**下方。

开发工具位于设置侧栏顶部，每个新窗口默认折叠。展开状态仅属于当前会话，语言切换原位更新标签，不会将其关闭。旧 `host.developerExpanded` 值会被忽略，不使偏好文件失效；新写入不再包含此字段。材质和诊断的展开状态仍作为宿主设置保存。

## 资源与修改方式

嵌入式扁平 JSON 资源位于 `src/DevDuo/Localization/en.json` 和 `src/DevDuo/Localization/zh-Hans.json`。`Host/AppLocalization.cs` 负责语言解析、显示文本格式化和偏好存储。英语为回退资源；未知资源语言回退到英语，若当前资源和英语资源均没有某个键，则显示键名本身。

修改应用文本时：

1. 在两份资源中新增或修改相同的键，所有翻译均应非空。
2. 保留带编号的格式占位符及格式说明，例如 `{0}` 和 `{3:F0}`。用户可见消息通过 `AppLocalization.Format` 格式化，以使用所选语言的区域性。
3. 宿主组件在 `Localize()`（`HostAddressBar`、`HostSettingsPanel`）中刷新文本，由 `MainWindow.RefreshLanguage` 调用。刷新标签时保留已选值，并为新控件提供本地化的无障碍名称；带快捷键的提示使用 `Shortcut.Format`。
4. 原生外壳标签使用 `Shell.*` 键，通过独立的 `uiLanguage` 和 `uiStrings` 显示选项传入。保持 Swift 和 Windows 的键引用同步。开发者页面的实际标题和主机名保留原文。
5. 应用自带颜色实验室通过 `Fixture.*` 键及 `WebAssets/Pages/color-scroll.html` 中的 `data-i18n` 属性标记文本。首次载入和后续更新均设置 HTML 语言。就地翻译通过专用演示页标记限制范围，并保留已选择的主题色提示。

应用自身的验证、加载、保存和初始化说明会翻译。操作系统或浏览器提供的异常详情保留原始语言，外层说明使用所选语言。即使初始化失败，Windows WebKit 的初始化及合成能力错误也能随语言选择更新。原生合成控件保留本地化名称及 `Accessibility.Press` 操作。

## 测量边界

应用界面本地化与实测场景数据分离。语言控件仅修改显示字符串，并重新配置现有原生容器；不会修改配置 ID、机身旋转、场景映射、遮罩、逻辑尺寸、视口预留、标签页框、裁剪或场景字号。八个机身姿态／折叠映射和 24 个 Safari 初始／滚动参考状态保持不变。

已知遥测值仅在宿主状态显示中翻译。保存的 JSON 和页面遥测保留规范键名、标识符、引擎名称及来源值。新增的 `uiLanguage` 和 `uiStrings` 是序列化容器选项中的显示元数据，也会出现在 `materialParameters` 下。应用语言选择器不会翻译任意开发者页面或校准页面，也不会伪造 iPhone 浏览器 API 或设备属性。

活动模拟标签显示当前文档的真实标题，不翻译；只有通用回退和非活动示意标签使用本地化。原生尾部省略沿用实测文字槽位和字体。切换语言可以改变回退文本长度，但不得改变实测几何。应用自带欢迎页和颜色实验室的译文可以重新排版；它们与规范校准页面和参考场景分开。

## 验证与限制

运行 `mise exec -- just test` 执行可移植测试，也可单独选择共享状态与本地化检查：

```sh
mise exec -- just test-core
mise exec -- just test-localization
```

`tests/DevDuo.Localization.Tests` 直接链接实际的本地化、配置、场景和容器选项源码，验证资源键与占位符一致性、非空文本、格式化、回退、显式／系统语言解析、语言偏好重启／损坏／写入失败行为、页面资源键、欢迎页翻译及不同语言载荷下实测选项值不变。`tests/DevDuo.Core.Tests` 单独检查宿主设置默认值／往返／字段校验、标定标签、URL 规范化、导航载荷、全部八个映射和 24 个状态、坐标变换、标题状态及滚动策略。两者使用仓库管理的 .NET SDK 和已提交锁文件，无需外部测试运行器。`just test-debugging` 检查真实回环 CDP 服务边界；`just test-windows` 执行独立的原生应用场景，会打开 Windows 窗口。

编译和可移植测试不能证明原生运行时正确性。macOS 需要另行验证页面已加载及滚动后的语言切换、原生辅助功能标签、模式／设备选择保留、颜色实验室、保存／错误消息和重启后的偏好恢复。比较切换前后的视口和原生框遥测。Windows 也需要相同的运行时检查，另需覆盖 Windows WebKit 错误路径、输入和 DPI 行为。仅通过 Windows 交叉编译不能证明这些运行结果。参见[平台对齐与macOS验收](015-PLATFORM-PARITY.md)、[Windows 交接](009-WINDOWS-HANDOFF.md)及[验证](003-CALIBRATION-WORKFLOW.md)。

需要隔离原生验收时，可在进程启动前通过 `DEVDUO_PREFERENCES_PATH` 指定独立偏好文件。Windows 测试使用操作系统临时路径，避免浏览器/原生崩溃覆盖用户真实设置；这不改变偏好格式或运行时语言行为。
