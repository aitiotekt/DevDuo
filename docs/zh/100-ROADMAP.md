# 宿主 UI 路线图

当前应用是带基础选择器、URL 框、开关和材质滑块的标定工作台。后续改进设备预览之外的桌面界面，同时保留测得的设备 viewport 与 Safari 外壳。

App 已具备持久化英/简中本地化与即时语言切换。后续调整宿主控件时持续维护两份资源和无障碍标签；地址栏导航及以下视觉设计工作仍待实施。

## 第一阶段：真实浏览器控制

- 将简单 URL 输入改成绑定活动原生 WebView 的真实宿主地址栏：重定向后的地址、页面标题、加载/失败状态、Enter 导航、后退/前进、刷新/停止以及清晰校验。保留 query/fragment，只向本地标定页添加测量标签，不污染任意开发 URL。
- 建立共享导航状态/回调及 WKWebView、WebView2 实现。目前宿主没有完整历史/加载绑定，多项设置会重建视图；应尽量保留已加载页面，并明确重置行为。
- 按用途分组展示折叠、角度、容器、比例、外框和展开标签栏开关。解释禁用项，明确选中值，设计并记录偏好持久化与重置。

宿主地址栏与模拟设备内部的 Safari 地址表面职责不同。后者属于标定场景，应保留测量框、悬浮行为和页面衍生外观。多标签开关只表示外壳变体，不隐含完整标签管理器。

## 视觉与交互

统一字体、间距、按钮尺寸、图标、focus/hover/pressed 状态及明暗主题，用 Avalonia 资源和可复用控件实现。设备预览是视觉重点，可选材质参数和详细指标进入次级面板。主要状态区应呈现可操作的加载/错误信息，不散布实现细节。

支持响应窗口、键盘导航、无障碍标签/提示、对比度和地址聚焦/刷新快捷键，保证 Windows DPI 和 macOS 预览比例下可用。未验证平台组合能力之前，不将普通 Avalonia 控件覆盖原生浏览器子视图。

## 验收边界

保留两种容器、八个机身/折叠映射、展开单/多标签、滚动转换、独立内外路径和实际 CSS viewport。宿主面板可以改变可用显示空间，但不能悄然改变逻辑设备尺寸，修改前后用相同设置核对状态。

Safari 组件、系统玻璃、硬件模拟和设备几何是分别需要证据的工作，不通过通用视觉重设计替换测量框或声称光学等价。先完成 [Windows 原生验收](009-WINDOWS-HANDOFF.md)，再安排平台 UI 完善。
