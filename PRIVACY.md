# Privacy

DevDuo's calibration receiver and diagnostics write local files. No separate analytics or hosted telemetry collector is implemented. Browsing a developer-selected remote URL still connects to that website using the system browser engine; the tool does not make remote browsing anonymous.

The measurement page records viewport/screen metrics, safe areas, selected labels, environment information and its URL. The receiver adds timestamps, an opaque record ID and the connection source address. Desktop observation includes scroll/viewport information, page title, hostname and page-derived colors. Native capture workflows can also record simulator identifiers, browsing titles/URLs, screenshots, videos, accessibility trees, tool output paths and source hashes.

Raw records belong in ignored `captures/`, `measurements/` or `.local/`. Generated diagnostic output under `temp/` can also contain private metadata. Windows WebKit persists website data, including localStorage, IndexedDB, persistent cookies and caches, under the current user's local application-data `DevDuo/WebKit` directory. `DEVDUO_WEBKIT_PROFILE` selects an explicit absolute profile directory, including isolated test profiles. Former browser-engine profiles are not migrated or automatically removed. Inspector Network/Storage/Console views can expose website data; exported diagnostics and screenshots need review before sharing. `DEVDUO_OUTPUT_DIR` can redirect desktop state output. The desktop host keeps language and host settings, including the last opened http/https page address, in local application data under `DevDuo/preferences.json`; **Reset settings** keeps that address and website data, and deleting the preferences file removes only host preferences. Deleting evidence or a browser profile is a deliberate local user operation; DevDuo does not implement an automated retention policy.

Public configuration retains selected simulator measurements, source-relative file references and evidence hashes. It omits the original raw sessions. Before sharing a report, review both metadata and images, and publish a sanitized derivative without changing original evidence bytes. Never publish secrets, personal host/account names, local network device or VLAN numbers, actual IP/MAC addresses, internal domains, simulator identifiers, private page contents or private absolute paths. Loopback endpoints and reserved documentation addresses are controlled examples, not personal network inventory; the application-owned `devduo.local` fixture host is also public test data.

`just public-audit` scans tracked and addable working-tree files, including documentation and hidden workflow files, and validates reviewed reference image dimensions/metadata. It checks private network ranges, contextual literal host addresses, workstation/device names, internal domains, MAC addresses and private paths without echoing matched text. `just public-audit-index` additionally scans staged text, so an older unsafe staged version cannot be mistaken for its corrected working-tree copy. Both commands are read-only and do not stage fixes. Before committing, include reviewed corrections and rerun the staged check; textual pattern checks cannot prove arbitrary images or Git history contain no personal information. Raw ignored evidence stays private and unchanged.

The checked-in Safari reference gallery is explicitly reviewed canvas derivatives showing only the controlled local fixture and simulator UI, without the Device Hub device list or desktop controls. Its manifest excludes raw browsing/environment records and tab UUIDs. The publication audit verifies the exact reviewed image names, dimensions and absence of embedded EXIF/XMP/ICC metadata; it does not replace visual or rights review.

See [Reference data](docs/en/002-MEASUREMENT-CONTRACT.md) and [Security](SECURITY.md).

Optional remote debugging exposes page data and permits page inspection and JavaScript evaluation to connected clients. CDP discovery includes the page title and URL; console, DOM, storage and observed network data may contain credentials or private content. CDP uses stable credential-free base/discovery/socket addresses. An explicitly configured bearer token is stored as plaintext in the local preferences file, masked in the settings field, excluded from general host serialization and copied addresses, and sent by agent clients through Authorization headers. It stays configured across service/app restarts; listener enablement still does not persist. The internal frontend URL can carry a separate temporary socket capability, which changes on every service start and must be removed from shared screenshots, logs or reports. Default binding is loopback. Explicit LAN binding makes the service reachable on active IPv4 interfaces. Windows native remote inspection uses WebKit's separate unauthenticated TCP transport; macOS uses system Safari discovery and does not open a CDP listener for that switch. Neither remote service starts automatically from saved preferences. Closing a container or disabling its service releases its listener/connections. Current-document chobitsu hooks cannot be safely undone; disabling mutes the bridge and removes future injection, and only a user-requested page refresh clears those hooks.

Custom page proxies receive website traffic according to the native engine's proxy rules. DevDuo accepts proxy endpoints without embedded credentials, stores the chosen mode/endpoint in local preferences and does not implement proxy authentication. The packaged chii frontend and chobitsu backend are served locally without fetching a CDN or starting Node. Page requests, source-map/resource requests made during inspection and normal website connections still follow the page/engine security and network rules.

The optional REST control service exposes current URL/navigation, host settings and native/page telemetry to local clients. Its separate port and optional bearer token persist in preferences; the token has the same plaintext storage, masked display and diagnostic-exclusion policy as the CDP token. Enablement is never saved. Swagger UI keeps entered authorization only in memory; refreshing/closing it clears that entry. Documentation assets are offline and external specification validation is disabled.

Native screenshot requests return webpage-viewport or composed-device image bytes to the requesting REST/CDP client without saving a server-side image. Device capture is restricted to the current process's window and crops the phone canvas; it does not capture other applications. Images can contain page content and should be reviewed before sharing.
